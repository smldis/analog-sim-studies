# Analog Sim Studies

Seven units compose one author-plan-execute-evaluate path.

**Start with Hedloom.** It is the front door, and it composes the three units
beneath it: `hedloom-flow` authors a Plan, `hedloom-exec` owns one attempt's durable
record, and `hedloom-run` walks the Plan and executes it. `sidecar-edits`,
`spice-canonical` and `netlist-decomposition` contribute netlist preparation,
canonicalization and structural recognition. The OTA/PVT reference composes
all seven into one inspectable Plan.

<summary><strong>Design record</strong> — working material, not documentation of what exists</summary>

Kept because the reasoning behind a boundary is worth more later than the
boundary itself, and separated because a reader looking for how the system
behaves should not have to walk through it first. Also in the sidebar.

- [Open concepts](vision/open-concepts.md) — the register of concepts raised
  and deliberately not built, each with the argument for deferring it. Read it
  before proposing anything; the objection may already be recorded.
- [Documentation open points](vision/documentation-open-points.md) — questions
  the documentation pass could not settle, with a file and line for each.
- [Conceptual flow foundation](vision/conceptual-flow-foundation.md),
  [Hedloom Flow rebuild](vision/hedloom-flow-rebuild-main.md) and
  [deferred study-runtime research](vision/deferred-study-runtime-research.md)
  — the arguments that produced the current units.
- [Manifesto challenges](vision/manifesto-challenges.md) and the
  [change catalog](vision/manifesto-change-catalog.md) — where the manifesto has
  been tested against practice, and what follows from that.

The child page under **Units** is generated by `python composition.py docs`
and is not maintained source.

The OTA/PVT reference is root-owned composition evidence only: it declares an
inspectable static Plan across child and unimplemented domain boundaries
without executing them, and introduces no adapter, runtime state, or new
component.

</details>
